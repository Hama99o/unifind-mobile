## 2. Bugs, ranked by severity

Each bug has a FlowApp card. Screenshot paths are relative to `~/Downloads/unifind-qa/shots/`.

### BLOCKER

**BUG-01: Login impossible on device: Auth0 "Callback URL mismatch"** (FlowApp #394)
- Repro: Profile (or any gate) → Sign In → the Auth0 page shows "Oops!, something went wrong · Callback URL mismatch".
- Cause: the redirect URI the app sends is not allow-listed in the Auth0 app. The code is correct (`src/services/authService.ts:78-98` login, `:556-580` logout).
  - EAS/APK and dev-client build send `unifind://auth/callback` (from `app.json` scheme `unifind`) for both login and logout.
  - Expo Go sends `exp://<host-ip>:<port>/--/auth/callback` (on this emulator: `exp://10.0.2.2:3011/--/auth/callback`). It changes with the IP and port.
- Fix (dashboard, tenant `dev-gim0725gfieuvjxt.us.auth0.com`, client id `lx7YKr…`): add `unifind://auth/callback` to **Allowed Callback URLs** and **Allowed Logout URLs** (plus the exp:// URL for Expo Go testing). Test login on an EAS dev/preview APK, not Expo Go.
- Impact: 12 board cards and every logged-in feature are blocked.
- Screenshot: `en/m23-auth0-after-wait.png`

### MAJOR

**BUG-02: Language not saved; native RTL never applied** (#395)
- Repro: Home → tap **AR** → app is Arabic, but the bottom tab bar still has Home on the left. Close and reopen the app → back to English.
- Cause: `src/screens/HomeScreen.tsx:72` only calls `i18n.changeLanguage(next)`. Nothing saves the language, and `applyDirection()` (`src/i18n/index.ts:30`, which calls `I18nManager.forceRTL`) is never called, so only screens that flip themselves with inline styles look RTL.
- Expected: choice saved (e.g. `expo-secure-store`/AsyncStorage key `lang`, read at boot before i18n init), `applyDirection(lng)` + `Updates.reloadAsync()` on change; tab bar, back gesture and default alignment mirrored.
- Screenshots: `ar/a00-cold-restart.png`, `ar/a01-home-top.png`

**BUG-03: Growth Center shows no offerings in Arabic** (#396)
- Repro: switch to AR → Growth Center tab. The header says "2 نتيجة" (2 results) but the list shows the empty state "لا توجد نتائج". In English the 2 cards show.
- Likely cause: the count and the list items come from different queries or locale params (FindOfferingsScreen / offerings list API with `locale=ar` and no fallback to the `en` entry). Compare with the web `find/offerings` query for ar.
- Screenshot: `ar/a11-growth-center.png`

**BUG-04: SignInSheet stays open after leaving the screen and blocks the tab bar** (#397)
- Repro: as guest open `/compare` (the sheet opens on mount, `src/screens/compare/CompareScreen.tsx:64`) → navigate Home. The sheet still covers Home; taps on the tabs do nothing until X or Back. In one run two sheets stacked and needed two Backs.

### 6.3 Exact fix pattern (FlowApp #404, #405)
1. **Defaults** in `app/_layout.tsx`:
   ```ts
   const queryClient = new QueryClient({
     defaultOptions: { queries: { staleTime: 5 * 60_000, gcTime: 30 * 60_000, retry: 1, refetchOnWindowFocus: false } },
   });
   ```

   Add `focusManager` + `AppState` (and `onlineManager` + NetInfo) wiring for React Native.

   ```ts
   export const useProgramDetail = (slug: string, locale: string) =>
     useQuery({ queryKey: ["program", slug, locale], queryFn: () => programDetailApi.get(slug, locale), enabled: !!slug });
   ```
   In the screen, show the skeleton only when `isPending && !data`, and use `isFetching` for a small refresh indicator.
